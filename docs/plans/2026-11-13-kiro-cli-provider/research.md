## A. How Echo runs an agent CLI today (read from the code)

Paths are relative to the repo root; the daemon crate is `crates/hub/src/` (package `echoctl`).

- `cli.rs`: `enum Cli { Claude, Codex }` (L13-17). `parse` (L23), `name`/`program` (L32-39), `model_arg` (L44), `has_session` (L60), `look`/`prompt_lines`/`turn_ended`/`trust_keys` (L68-99), `args` (L101). `Start` (L111) is the CLI-neutral launch description: `title, prompt, dirs, plugins, model, effort, tools, worker, session_id, resume, first, extra`. `claude()` (L135) and `codex()` (L225) build the arguments. `Choice` and `pick()` (L278-320) pick the CLI and model from four levels. `COMING = ["opencode","gemini"]` fail with "not supported yet".
- Codex is the template for a CLI that sets its own session id: its `-c hooks.SessionStart=...` runs `echoctl notify`; `main.rs::notify` (L1059-1105) sees `hook_event_name == "SessionStart"` and calls the daemon's `session` RPC; the daemon stores the id with `db::set_worker_session` / `db::set_agent_session` (`daemon.rs` ~L1585); resume is `codex resume <id>`; `has_session` globs `~/.codex/sessions`. Decision: `docs/decisions/features/0037-codex-runs-as-a-second-agent-cli.md`.
- Spawn paths: `daemon.rs::open_agent` (Orchestrator and Normal session, ~L659-815), `spawn_for` (Worker, ~L1682), `start_worker` (~L1780). Env for all: `agent_env` (~L1736): `PATH` with echoctl first, `ECHO_REPO`, `HUB_STATE`, `HUB_WORKER`/`HUB_AGENT`, `TERM`, `COLORTERM`. `env_remove: inherited_agent_vars()` drops `CLAUDECODE`, `AI_AGENT`, `CLAUDE_CODE_*`, `ORCA_*`, `CLAUDE_PID`, `CLAUDE_EFFORT` (`is_agent_var`, ~L3207).
- Screen reading (`screen.rs`): `Look { TrustPrompt, PermissionPrompt, Working, Waiting, Idle }`. `watch` (Workers, ~L2164) and `watch_agent` (~L2936) tick every second and call `live.cli.look(screen)`. `decide` (~L2871) approves a permission prompt with Enter and denies with Esc; `chat.send` types text, with bracketed paste for several lines, then Enter after 150 ms (`type_in`). The terminal is 45 rows by 160 columns (`pty.rs`).
- Claude-only parts that Kiro will not have in milestone 1: `chat.rs` / `chat_read` (returns `supported:false` when the agent's cli is not "claude", `daemon.rs` ~L421), `run_usage` (`claude -p /usage`), `stats.rs`, `renew_if_due` (reads Claude transcripts), the `mod/` plugin, `screen::activity`.
- Profiles (`profile.rs`): `cli` must pass `Cli::parse`; `tools` is a comma list of Claude tool names; `profile::start` builds the `Start`. The shipped profiles say `cli: claude`.
- Prompts: `orchestrator.md` and `worker-contract.md` (in the echo repo's hub dir) say to run `echoctl wait` as a background Bash command (`run_in_background: true`) that Claude Code wakes the Orchestrator from, and to run `echoctl ask` with the Bash tool and a 600000 ms timeout. Kiro's tool names and background behaviour are unchecked (spike Q8).
- Swift: `app/Sources/HubCore/Models.swift:600` `agentCLIs = ["claude", "codex"]` feeds the CLI picker in `app/Sources/HubApp/AgentSettings.swift:115-140`; `AppModel.models` (`AppModel.swift:116`) is the Claude-only model picker for new sessions; `AgentLine.short` (`ContentView.swift`) shortens `claude-opus-5-5` to `opus`; `Agent.Kind` labels a Normal session "Claude Code" (`Models.swift` ~L49); the chat composer says "Reply to Claude…" (`ChatView.swift`).
- Tests: `crates/hub/tests/daemon.rs` runs the daemon with `HUB_TEST_AGENT=crates/hub/tests/fake-agent.sh`; with it set, `spawn_for` and `open_agent` skip `Cli::args`. Unit tests live next to the code (`cli.rs` tests L~455-497, `screen.rs` tests with `CODEX_*` fixtures).

## B. Kiro CLI facts (this machine: `kiro-cli 3.2.1`, signed in with IAM Identity Center)

Sources: https://kiro.dev/docs/reference/cli-commands/ , https://kiro.dev/docs/custom-agents/configuration-reference/ , https://kiro.dev/docs/hooks/types/ , https://kiro.dev/docs/cli/headless/ , and `kiro-cli chat --help` run locally.

- Binary `kiro-cli`; `kiro-cli chat [OPTIONS] [INPUT]`. Options seen locally: `-r/--resume`, `--resume-id <ID>`, `--resume-picker`, `--agent <AGENT>`, `--model <MODEL>`, `--effort <low|medium|high|xhigh|max>`, `-a/--trust-all-tools`, `--trust-tools`, `--no-interactive`, `--trust-workspace` ("skip the Trust this workspace prompt for this launch only"), `-l/--list-sessions`, `--list-models [--format json]`, `--v3`, `--v2`, `--output-format stream-json`. There is no `--session-id`, `--add-dir`, `--system-prompt` or `--settings`.
- Models here (`kiro-cli chat --list-models`): `auto` 1.00x credits, `claude-opus-5.5` 2.00x, `claude-sonnet-5.5` 1.30x, `claude-haiku-5.5` 0.06x, `gpt-5.6-sol` 4.40x, `gpt-5.6-terra` 2.20x, `gpt-5.6-luna` 0.60x, `claude-opus-5` / `claude-sonnet-5` 2.20x / 1.30x, `claude-opus-4.8`..`4.5`, `deepseek-3.2`, `minimax-m2.5`, `glm-5`, `qwen3-coder-next`, and others. Ids use a dot.
- Custom agents: `.kiro/agents/<name>.md` (workspace) or `~/.kiro/agents/<name>.md` (global); Markdown with YAML front matter (`name`, `description`, `model`, `tools`, `excludedTools`, `includeMcpJson`, `mcpServers`, `resources`, `permissions`, `hooks`, `welcomeMessage`), the body is the system prompt. JSON form has `prompt` (inline or `file://`). `~/.kiro/agents` already holds `hinata.md ino.md jiraiya.md kakashi.md naruto.md sasuke.md shikamaru.md` (the human's own agents; Echo must not touch them).
- Permissions in an agent file: `permissions.rules: [{capability: shell|fs_read|fs_write|web_fetch|mcp|subagent..., match: [globs], effect: allow|ask|deny, exclude: [...]}]`; deny always wins.
- Hooks in an agent file (V3): array of `{name, trigger, matcher?, action: {type: command, command}}`; triggers `SessionStart` (alias `agentSpawn`), `Stop` ("Agent Stop"), `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `SessionEnd`, `PreCompact`, `PostCompact`. Event JSON on stdin includes `hook_event_name`, `cwd`, `session_id` (documented sample for SessionStart shows `"hook_event_name": "agentSpawn"`).
- Sessions: saved per turn; `~/.kiro/sessions/<workspace id>/sess_<uuid>/` holds `session.json` (`id`, `title`, `workspacePaths`, `modelId`, `createdAt`, ...) and `messages.jsonl` (lines of `{id, timestamp, payload}`); `~/.kiro/session-index/`, `~/.kiro/session-leases/`. `KIRO_HOME` overrides the whole `~/.kiro` (sign-in, sessions, agents). Session ids are UUIDs prefixed `sess_`.
- Not found in the docs: the exact screen text of Kiro's TUI (idle, working, permission prompt), the approve/deny keys, whether a shell command can run in the background and wake the agent, which environment variables mark a nested Kiro, how folders outside the workspace are allowed.
